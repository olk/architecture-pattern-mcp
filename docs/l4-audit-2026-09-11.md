# L4 FizzBee Verification — External Audit (2026-09-11)

An independent audit of the L4 (FizzBee) verification layer: are the models
faithful to the implementation, does the gate mean what `verify/fizz/README.md`
says it means, and is the vacuity story real rather than aspirational.

**Verdict: the L4 layer is correct against its documented scope.** Every claim
in the ledger was either re-derived here or converted into a mechanical gate
during this audit. Two coverage gaps were found and closed in the same change
(FG-32/FG-33, below).

## Methodology

1. **Problem decomposition** (Shannon-style): gate semantics → model→code
   faithfulness (per spec) → conformance-replay soundness → vacuity/garden
   honesty → ledger drift controls → honest-claims boundary.
2. **Toolchain ground truth** re-derived from external sources rather than the
   repo's own docs: upstream `main.go` (default options: `crash_on_yield=true`,
   `max_concurrent_actions=min(2, max_actions)`; liveness = strict SCC/cycle
   check; `exists` = state-graph witness scan; exit code is 0 on invariant
   failure — only panics exit non-zero), the FizzBee language reference
   (`fair` = weak fairness; `any` deprecated alias of `oneof`; actions take no
   parameters) and the liveness tutorial (stutter-only schedules count as
   violations unless a fair action is continuously enabled; bounded fair ticks
   keep non-terminal regions cycle-free).
3. **Empirical probes**, all green:
   - `make verify-fizz`: all 7 specs PASS exhaustively; state counts match the
     README run-stats table exactly (design_loop 154, jobs_protocol 307,
     jobs_runner 458, pipeline_control 196, reasoning_retry 4213,
     retrieval_fusion 4, tei_fallback 19).
   - `tests/verification/test_fizz_conformance.py` +
     `test_fizz_traces.py`: 143 passed.
   - `make verify-ledger`: 34 rows / 26 referenced IDs / 12 artifacts,
     consistent.
   - Manual counterexample reproducers: FG-01 (`GUARDED=False` →
     `J1_TerminalImmutable` violation with the W0-1 terminal-write-race
     trace), FG-09 (dropped `FailRun` guard → `FP6_NoPrematureFailure` at
     attempts=0), FG-16 (unfair `RunFinish` → `FP5_EventualOutcome` liveness
     failure).
4. **Spec-by-spec model→code review** against
   `src/tools/jobs.py`, `src/tools/submit_architecture_design.py`,
   `src/tools/cancel_architecture_design.py`, `src/pipeline.py::design_loop`,
   `src/reasoning/client.py`, `src/patterns/safe_tei_rerank.py`, and
   `src/patterns/retriever.py` (the latter two pinned empirically by the L4
   conformance replay, including its planted-mutant vacuity tests). Every
   abstraction was checked for both directions: a wrong model must fail the
   conformance guard-agreement check whether it is over- or under-restrictive.

| # | Finding | Disposition |

## Scope of the license (unchanged, restated)

A green L4 run licenses exactly: *no interleaving up to the stated bounds
(`fizz.yaml`: max_actions 2000, max_concurrent_actions 2; per-spec
tightenings) violates the assertions*. It does not judge design quality (T2),
does not cover process-restart orphaning beyond the FC-1 ownership qualifier,
and its conformance replay pins model→code agreement for 3 of 7 specs
(`jobs_protocol`, `tei_fallback`, `retrieval_fusion`); the other four
(`jobs_runner`, `pipeline_control`, `design_loop`, `reasoning_retry`) keep
their real-code coverage in L1/L2/L6 per the ledger. `verify-fizz-simulation`
remains a nightly probabilistic relief valve, never the authoritative check.
